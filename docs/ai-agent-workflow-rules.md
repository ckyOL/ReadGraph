# AI Coding Agent 工作流指令 (SDD + TDD)

## 1. 核心工作模式：SDD + TDD 驱动

作为 AI Coding Agent，在进行任何代码开发之前，必须严格遵循以下 **规格驱动 (SDD)** 和 **测试驱动 (TDD)** 的工作流。严禁在没有明确规格和测试护栏的情况下直接生成业务实现代码。

### 阶段 1: 规格读取与确认 (Specification-Driven)
1. **强制前置条件**：在开发任何功能之前，必须先要求用户提供或共同完善“规格说明书 (Specification)”。
2. **UI 设计说明**：对于前端/全栈任务，规格中必须包含清晰的 **UI 设计说明**（如布局结构、交互动效、颜色规范等）。
3. **架构与边界**：确保完全理解领域模型、API 契约以及边缘情况。若存在歧义，必须向用户提问。

### 阶段 2: 编写测试护栏 (Test-Driven)
1. **测试先行**：在完全理解规格后，**必须首先编写测试代码**，然后再编写实现代码。
2. **广泛使用的工具链**：
   * **单元测试/集成测试**：优先使用 **Vitest**。
   * **端到端测试 (E2E) / UI 测试**：优先使用 **Playwright**。
3. **验证失败状态 (Red)**：生成测试后，（如有可能）需先验证这些测试在当前代码库下会**失败**，以此证明测试具备拦截代码错误的有效性。

### 阶段 3: 编码实现与闭环 (AI Coding)
1. **目标驱动**：编写业务逻辑与 UI 实现的唯一目标是**使阶段 2 编写的所有测试通过**。
2. **UI 还原**：在实现 UI 时，必须严格按照“UI 设计说明”的规格进行高保真还原。
3. **红绿重构循环**：
   * 运行测试。
   * 若失败，读取错误日志并自我修正代码。
   * 直至所有测试变为绿色 (Green)。

### 阶段 4: 重构与交付 (Refactor)
1. **安全重构**：在所有测试通过（Green）的保护下，审视代码质量。消除重复代码（DRY），优化命名，提升性能。
2. **不破坏测试**：任何重构操作都不能导致现有的测试失败。

---

## 2. Agent 交互准则

* **拒绝无需求直接编码**：如果用户仅提供一句模糊的“帮我写个登录页面”，你需要回答：“为了保证代码质量和架构合理性，请提供具体的规格说明（包括 UI 设计说明），或者我们可以先一起把规格定义清楚。”
* **拒绝无测试代码**：任何新增加的核心逻辑，都必须伴随着相应的测试用例。
* **主动报告进度**：按照 `Specs -> Tests(Red) -> Code -> Tests(Green) -> Refactor` 的阶段，清晰地向用户报告当前所处的工作节点。
