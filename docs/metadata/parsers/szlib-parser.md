# Shenzhen Library (深圳图书馆) Parser 设计

> AI Agent 指引：针对深圳图书馆“我的图书馆”查询接口返回的纯流通记录 JSON 数据的解析器设计。

## 原始数据特征分析

文件示例：`record.json`
- **纯交易日志**：包含每一步的流通操作，而非书目合并后的报表。
- **缺失核心书目字段**：无 `ISBN`，无 `作者`，无 `出版社`，无 `出版年`。这要求系统在没有 ISBN 的情况下，完全依赖 `barcode` 进行书籍身份的确认和实体追踪。
- **时间字段分离**：日期 `date`（"YYYYMMDD"）和时间 `time`（"HH:MM:SS"）分离，且均未标明时区（默认 `Asia/Shanghai`）。
- **操作类型（optype）繁杂**：包含“读者借出”、“读者还回文献”、“自助查询”、“读者续借”等。

## 解析规则设计

### 1. 记录过滤
- **忽略** `optype` 为以下值的记录，不参与借阅周期的合成：
  - `"自助查询"`：与借阅状态无关的机器操作。
  - `"读者续借"`：根据设计决策，不影响整体借还周期（若未来需统计续借次数，可再次引入）。

### 2. 书目提取 (Book Extraction)
对于每一条有效流通记录（借或还），提取书籍实体：
- `id`: 生成新 UUID。
- `isbn13`: `null` (原数据无此信息)。
- `title`: 取自 `title` 字段。*(注：可能包含 "= 英文名 : 副标题" 等编目标记，原样保留)*。
- `authors`: `[]` (空数组)。
- `classifications`:
  - 从 `callno` 中提取分类号：取 `/` 前的部分作为 `code`（如 "TP311.5/1040" → "TP311.5"）。
  - `system` 设为 `'clc'`（国内公共图书馆默认使用中图法）。
- `barcodes`: `[{ barcode: 原始记录的barcode, sourceId: 当前解析的sourceId }]`。

### 3. 借还周期合成 (BorrowCycle Synthesis)
使用 `barcode` 分组所有有效操作，按时间顺序（从早到晚）排序。

1. 时间转换：
   将 `date` ("20260411") 和 `time` ("18:33:50") 组合为 "2026-04-11T18:33:50"。
   由于时区为 `Asia/Shanghai`，需补齐时区偏移量 ("+08:00") 并转为 UTC (ISO 8601)。
2. 配对算法：
   - 遍历某条码号下的操作流。
   - 遇到 `"读者借出"`：开启一个全新的借阅周期。
   - 遇到 `"读者还回文献"`：
     - 若当前已有开启的周期，将其作为归还时间，闭合该周期。
     - 若无开启的周期（即“只有还没有借”，可能因为借出记录在导出的时间范围外），则创建一个状态为 `unknown` 的半闭合周期。

### 4. 数据去重与合并
由于深图数据**没有 ISBN 和作者**：
1. **精准定位物理副本**：依赖 `sourceId` + `barcode`。在数据库中查找是否已有该 `barcode`。如果有，则直接关联到已存在的 `Book` 记录上。
2. **模糊合并**：如果这是一个新的 `barcode` 且无 ISBN，仅凭 `title` 很难实现 100% 安全的自动合并。将其视为新书导入后，系统 UI 可提供“按书名建议合并”的功能，由用户人工确认是否与有 ISBN 的完整书目记录（比如通过微信读书导入的同一本书）进行合并。
